# UI rework — design handoff

- Status: Design decided for the first slice; flows G–N drafted (see end)
- Date: 2026-09-29
- Design source: Penpot, self-hosted at `penpot.lug.sh`, file **"Komorebi Design"**
- Scope: web app (`web/`), Home / discover first

This document is the single source of truth for implementing the reworked UI.
It records every decision made during Penpot prototyping so an implementer
does not need the design session. Where Penpot and this document disagree,
ask; do not guess.

## Goals

1. **Declutter the map.** The map is quiet until the rider asks something of
   it (progressive disclosure). Default view = basemap + curated routes only.
2. **Untangle the information architecture.** `NavigationPanel.svelte`
   (~1,200 lines) does search, directions, intent and live navigation at once.
   Split it into a search entry, a route card and separate plan flows.
3. **Credit the data.** Every data source is attributed where its data is
   visible, and a Data sources sheet lists all of them.
4. **One look.** Cloudflare Kumo's structure, gray-led (no brand hue).

## Visual system — Kumo, gray-led

Kumo (github.com/cloudflare/kumo) is React/Base UI. **Do not import it**
(the project avoids React). Port its tokens and styling to Svelte + Tailwind 4
semantic tokens in `src/app.css`.

Structure taken from Kumo: Inter; 8px radius on controls and cards (12px on
floating panels, 14px on dialogs); 1px low-contrast line rings; soft layered
shadows; 36–40px controls. Kumo's brand hue is replaced by neutral near-black.

Radii: sm 6, md 8, lg 12, pill 999. Spacing: 4 / 8 / 12 / 16 / 24.
Shadows: `xs` = 0 1 2 rgba(0,0,0,.08); `lg` = 0 8 24 −4 rgba(0,0,0,.12) plus a
1px 6% ring.

Semantic states: info `#1E40AF` (text only, never map lines), success
`#047857`, danger `#B91C1C`, warning — see open decisions.

### Colour rule

**One hue per meaning.** Chrome is neutral. Routes own blue. Each data layer
owns one ramp. Saturated colour appears only for data.

### Routes

| Token | Hex | Use |
|---|---|---|
| route | `#1A73E8` | curated routes at rest; the selected route |
| route-muted | `#90A4C3` | unselected routes when one is selected; all routes when data layers are on |
| route-casing | `#FFFFFF` | 1.5–2px each side of every route line |
| route-pressed | `#0B57D0` | hover / pressed |

Selected line ≈ 5px over a 9px white casing; resting 3px over 6.5px.

low `#A7F3D0` (0–2) · moderate `#FDE68A` (3–5) · high `#FB923C` (6–7) ·

### Greenery

green-100 `#DCFCE7` · green-300 `#86EFAC` · green-500 `#22C55E` · green-700
`#15803D` (bare → full canopy).

### Temperature (text readouts only)

Proposed: cold `#475569` · cool `#94A3B8` · mild `#71717A` · warm `#FB923C` ·
hot `#DC2626`. See open decisions.

### Difficulty — no colour

Neutral badge with 1–4 filled bars plus a label: Easy 1 · Moderate 2 · Hard 3 ·
Expert 4. Filled bar = text.default `#18181B`, empty bar = `#D4D4D8`, badge =
surface.tint + hairline, radius 6. Remove the `--color-easy|moderate|hard|expert`
tokens once nothing uses them. Medal colours and IMBA trail shapes were rejected.

### Map base (prototype values)

land `#F2F2F0`, road `#FFFFFF`, road casing `#E2E2DF`, building `#E9E9E6`,
park `#E6EBE3`, water `#D9E2E8`, label `#8A8A8E`. The production basemap stays
CARTO `light_all` (Positron) for now; these values describe the intended feel
if we move to a vector style.

## Markers (Penpot page "Markers")

- **Start:** white circle, 2.5px route-blue ring, route-blue bicycle icon.
- **End:** route-blue filled circle, 2px white outer ring, white flag icon.
- **Loop (start = end):** one combined marker — start marker plus a small end
  badge offset to its top-right. Decided over an overlapping pair.
- **Sizes by zoom:** z ≤ 13: 20px · z14–15: 24px · z16+: 28px. Soft `lg` shadow.
- **Waypoints/stops:** 22px white circle, 2px route-blue ring, number in route
  blue.
- **Venues (opt-in only):** 28px white circle, 1px line ring, line icon
  (Konbini, Café, Water, Repair). Selected = near-black fill with a white icon
  and a label chip. Off-route venues dim to 45% when a route is selected. Dense
  areas show a white count pill.
- **Your position:** dot with a white ring, accuracy halo and heading cone;
  stale/hidden = hollow gray (honest state, ADR 0007). Colour is an open
  decision.
- CARTO's style ships exactly one icon (`circle-11`, slate `#697B89`, city dots
  at z7–8 only). At cycling zooms CARTO draws labels only; all markers above are
  ours.

## Layout — Home / discover (frames A–E)

- **A · Resting.** Map + curated routes only. Top-left: search pill (wordmark,
  "Search places, or describe a ride", menu). Top-right: Layers button.
  Bottom-right: zoom + locate stack, then attribution pill. Bottom-left: a
  "3 curated routes in view" peek bar. Bottom-centre: time chip
  ("Now · 18° · light NE wind · dry") that expands into the time scrubber.
  Mobile: panels become a bottom-sheet peek holding the time chip.
- **B · Search focused.** The map dims. One panel under the pill: **Plan a
  route**, **Describe a ride** (LLM intent), SHOW ON MAP venue chips (Konbini,
  Café, Water, Repair — venues stay off until picked), RECENT items.
- **C · Layers + time.** Layers popover under the Layers button. CONDITIONS
  follow the time slider: Shade, Rain, Wind, Greenery — each row has a switch,
  a swatch and its source + licence line. ALWAYS-ON: Curated routes, Cycling
  infrastructure. The scrubber expands bottom-left (hour ticks, rain bars, Now
  button) with a legend above it. With layers on, routes use route-muted.
- **D · Route selected.** Selected route blue, others route-muted. Route card
  (desktop: left panel; mobile: half sheet): title, subtitle, difficulty +
  tag badges, stats (distance, climb, time at your pace), elevation sparkline,
  "Conditions if you leave at HH:MM" tiles (shade %, wind, rain), source line,
  actions (primary **Ride this**, **Customize**, save), then a disclosure row
  (Reviews · Stops · Surface).
- **E · Data sources sheet.** Opens from the attribution pill. Columns:
  source, used for, licence · freshness. A note that derived scores (shade,
  greenery) keep their sources' licences, plus a "Fix a map error on
  OpenStreetMap" link.

## Flows — frames G–N (Penpot page "Home rework", row "Flows")

Every flow opens from the search pill or the route card and returns to A.
One floating panel at a time on desktop (left, 400px); one sheet at a time on
mobile. The map never hosts more than one panel's worth of chrome.

### G · Plan a route

Opens from **Plan a route** in B, or **Customize** on a route card (stops
prefilled). The panel replaces the search pill.

- **Stops:** From (defaults to *Your location*), To, then **+ Add stop**.
  Each row has the start / waypoint / end marker glyph, a drag handle and a
  remove button; a swap button sits beside From/To. Hint: *or tap the map to
  drop a stop*. Stops stay in the URL (current behaviour).
- **Options row:** a *Leave now ▾* chip (the time chip's value, shared with
  the scrubber) and a *Preferences* chip that opens the rider profile (M).
- **Routes:** one row per alternative — Suggested, Fast, Quiet streets
  (renamed from "Avoid main roads"). Each row: name, time, distance, climb,
  and one conditions line (*64% shaded · light headwind · dry*). The selected
  row has a 3px route-blue leading bar; the others are plain.
- **Map:** the selected alternative is route blue, the others route-muted.
  Each alternative carries a time pill at its midpoint (white pill, muted
  text; the selected one is a route-blue pill with white text). Tapping a
  line or pill selects it. Curated routes hide while planning.
- **Actions:** primary **Ride this**, secondary **Save**, icon **Share**.
- **No route found** is a normal outcome (ADR 0004): the routes list is
  replaced by the reason and one fix (*Remove the 5% grade limit*, *Move the
  stop onto a public road*).

### H · Describe a ride

Opens from **Describe a ride** in B, or typing a sentence into the search
pill (two paths, one field). The model returns text references and
preferences only; Route Planning resolves the places (ADR 0003: no
model-made coordinates, ambiguity needs the rider's confirmation). The
rider confirms before anything is routed.

- A multi-line field with the rider's sentence.
- **Places** — one row each for **From**, **Via** (zero or more, in spoken
  order) and **To**, with the start / waypoint / end marker glyph, the
  resolved name and a context line (*Bridge · Taitō*), and a pencil to
  change it (opens the same place search as G). The resolved places appear
  on the map as markers with name labels; no route is drawn yet.
  - No "from" in the sentence → From = *Your location*, noted under the
    rows.
  - Ambiguous (*Kuramae — 2 places match*): the row is tinted warning, has
    a **Choose** button, and every candidate shows on the map with an
    orange "?" label. Picking a candidate on the map or in a list resolves
    it.
  - Not found: the row keeps the spoken text with *Not found — search*.
- **Preferences** — one removable chip per applied preference (*More
  shade*, *Quieter streets*, *Tailwind preferred*).
- *Not supported yet* lists what was heard but can't be honoured (detour
  budget, max grade), in text.subtle with a ⓘ explaining why. Never silently
  dropped.
- **Plan this route** is disabled until every place is resolved (helper:
  *Choose which Kuramae first*). It opens G with the stops filled in and
  the preferences shown as a summary line above the routes list; *Edit*
  returns here.
- Footer: *Places are matched with OpenStreetMap (Nominatim) — check them
  before you ride. Nothing is routed until you confirm.*
- Unavailable (503): the Describe entry stays visible but disabled, with
  *Describing rides isn't available on this server*.
- **Backend gap:** `RouteIntent` has no place fields today. Add
  `places: { from, via[], to }` as text references (plus unresolved terms)
  and resolve them in Route Planning, not in the adapter.

### I · Routes list

Opens from the "N curated routes in view" peek bar. A 400px panel with a
sort control (*Nearest · Shadiest now · Shortest*), filter chips (distance,
difficulty, loop only) and route rows (title, distance, climb, difficulty
badge, shade % now). Hovering a row highlights its line; the list follows
the viewport. Selecting a row opens D.

### J · Stops and errands

Inside G: **+ Add stop** also accepts a venue hashtag (#konbini, #cafe,
#water, #repair). A hashtag stop shows *Nearest Konbini along the route* and
resolves once routed; the map shows the chosen venue with the venue marker
and a dashed spur if it is off-line. Replaces the separate `/planner` page.

### K · Ride mode (mobile first)

**Ride this** → first-ride disclaimer (F, once) → location permission
(asked only now, ADR 0007) → ride mode.

- Top card, near-black: next instruction (turn glyph, distance, street).
- Map follows heading; the route ahead is route blue, the ridden part
  route-muted; position dot per the open decision.
- Bottom strip: remaining distance and time, arrival clock, and one
  conditions-ahead line (*Shade for the next 2.1 km*, *Rain from 14:20*).
- Large targets (≥ 56px) — **End ride**, mute, recentre. No other chrome.
- Screen stays readable at arm's length: 20px+ for the instruction.

### L · Ride-mode honest states (ADR 0007)

- **Off route:** the top card turns white with a warning edge: *Off route —
  Reroute* (primary) and *Back to route* hint with distance.
- **Weak GPS:** accuracy halo grows; banner *GPS is weak — position may be
  off by 60 m*.
- **Guidance paused:** after the page was hidden: *Guidance paused while
  Komorebi was in the background* with **Resume**. Never imply it kept
  running.
- **Offline:** the planned route and its instructions stay; conditions show
  their last-updated time.

### M · Your riding (profile sheet)

From the menu, or the Preferences chip. Stored in the browser only (ADR
0006), said plainly: *Saved on this device. No account needed.* Contents:
pace (km/h, with *estimated from your rides* when known), shade / greenery /
tailwind sliders (0–100, the same values the intent chips set), language
(EN / 日本語), **Export** and **Reset**. About, Data sources, Terms of use.

### N · Empty, loading and error states

- **Loading:** skeleton rows in panels; the map never blocks. Route lines draw
  when ready; no spinners over the map.
- **Empty viewport:** the peek bar says *No curated routes here — zoom out*
  with a **Zoom out** action.
- **API unreachable:** a single toast pill above the time chip: *Can't reach
  Komorebi — showing the map only* with **Retry**.
- **Layer unavailable:** the layer row in C shows *Unavailable · updated 09:00*
  and its switch is disabled; the scrubber hides its rain bars.

### Mobile B, C, E

- **B:** full-screen search sheet; the keyboard pushes the Plan / Describe
  rows to the top; venue chips scroll horizontally.
- **C:** layers as a bottom sheet (same rows as desktop); the scrubber docks
  above it at full width.
- **E:** the Data sources sheet is a full-height sheet with one card per
  source instead of columns.

### Dark mode

Chrome tokens only; data ramps and route colours stay (they are already
chosen to read on a light basemap and on CARTO Dark Matter). Dark chrome:
canvas `#09090B`, base `#18181B`, elevated `#27272A`, line `#3F3F46`,
hairline `#27272A`, text.strong `#FAFAFA`, text.default `#E4E4E7`, subtle
`#A1A1AA`, primary `#FAFAFA` with on-primary `#18181B`. Route casing becomes
`#18181B`. Basemap: CARTO `dark_all`. Follows the system setting; ride mode
switches automatically after sunset.

### Cycling infrastructure layer

Always-on, quiet: protected tracks as a 2px zinc-600 `#52525B` line along the
road, painted lanes dashed. Neutral so it never competes with route blue or
the greenery ramp.

## First-ride disclaimer (frame F)

Shown once, when the rider first taps **Ride this**; always reachable from
Menu → About. The language follows the device locale, with an EN / 日本語
switch. Japanese uses **Noto Sans JP** (Inter has no Japanese glyphs). Draft
copy — **needs legal review** (Japanese consumer law limits blanket liability
exclusions) **and a native-speaker review** before shipping.

**EN** — Title: *Before you ride*. Lead: *Komorebi helps you plan. It can't see
the road you're on.*

1. **Estimates, not guarantees** — Routes, shade, rain and wind come from open
   data and forecasts. They can be incomplete, out of date or wrong.
2. **The road comes first** — Always follow road signs, signals and Japanese
   traffic law. What you see on the road overrides the app.
3. **Respect private property** — Routes can run past gates, estates or paths
   that are private or closed. If a sign says no entry, don't go in — turn back
   or find another way.
4. **Hands off while riding** — Don't operate your phone while riding. Stop
   somewhere safe before you touch the screen.
5. **You ride at your own risk** — Komorebi isn't liable for accidents,
   injuries or losses from using the app.

Button: *I understand*. Links: *Terms of use · Data sources*. Footer: *Shown
before your first ride. Always available in Menu → About.*

**JA** — タイトル: *ご利用前に*。リード: *Komorebiは走行計画をお手伝いしますが、実際の道路状況は把握できません。*

1. **表示は推定です** — ルート・日陰・雨・風の情報は、オープンデータと気象予報に基づく推定です。不完全、古い、または誤っている場合があります。
2. **実際の道路が最優先** — 必ず道路標識・信号・道路交通法に従ってください。アプリの表示よりも、実際の道路状況を優先してください。
3. **私有地に立ち入らない** — ルートが私有地や通行止めの道を通る場合があります。「私有地」「立入禁止」などの表示がある場合は進入せず、引き返すか別の道を選んでください。
4. **走行中は操作しない** — 走行中にスマートフォンを操作しないでください。操作は安全な場所に停車してから行ってください。
5. **ご自身の責任でご利用ください** — 本アプリの利用により生じた事故・怪我・損害について、Komorebiは責任を負いかねます。

ボタン: *理解しました*。リンク: *利用規約 · データ出典*。フッター: *初回走行前に表示されます。メニュー → このアプリについて からいつでも確認できます。*

## Implementation rules (from the repo)

- Follow `web/AGENTS.md`: Svelte 5 runes, shared state in `src/lib/stores/`,
  MapLibre only through the shared Map component; finish with `npm run check`,
  `lint`, `format:check`, `check:tokens`, `build`.
- `npm run check:tokens` bans arbitrary Tailwind values, raw palette classes
  and inline hex in components — every new colour becomes a semantic token.
  Hex stays legitimate only in MapLibre paint (`Map.svelte`,
  `conditionColors.ts`).
- Layout tests are mandatory under `web/tests/` and must follow
  `web/tests/AGENTS.md`: role/name locators, no sleeps, 44×44 hit boxes, a
  fully-in-viewport check, focus reachability.
- Routing already avoids private roads as a soft cost (PR #2). Flagging
  private segments in route responses is a separate backend follow-up.
